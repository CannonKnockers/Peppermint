# Security policy

Peppermint runs commands and changes desktop state on the user's computer.
Security reports are therefore handled privately whenever possible.

Do not open a public issue for a vulnerability or for a report that contains
credentials, private logs, or personal data. Use GitHub's private vulnerability
reporting feature when it is enabled for the repository. If it is not enabled,
contact the repository owner privately with:

- a concise description of the issue;
- the affected version or commit;
- reproduction steps or a proof of concept that does not destroy data; and
- the impact and any suggested mitigation.

Do not include passwords, access tokens, private keys, or complete local
database files in a report.
